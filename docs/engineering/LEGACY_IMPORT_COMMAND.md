# 六站共用：離線匯入操作入口

## 架構文件

操作員先停止站台及未協作寫入程序，在具備受限檔案存取權的主機執行 `station-server --legacy-import`。目標資料庫由 `SUITE_DB` 設定、快照目錄由 `SUITE_MIGRATION_BACKUP_DIR` 設定；工作階段、備份、身分對應、使用者 ID、組織 ID、確認用的目的組織與重試鍵只從標準輸入讀入 JSON，不放命令列。協調器取得維護鎖、建立快照及原子交易後，標準輸出僅回傳筆數與快照檔名；錯誤不輸出原始請求、工作階段或主機檔案路徑。

此介面是本機操作工具，並非瀏覽器 API；維護鎖不阻止其他不使用協定的工具。設計和 CI 通過不代表可直接對生產資料執行：必須先完成受控還原演練、權限及跨程序驗收。

## 程式邊界

- `SUITE_DB` 必須明確指定既有資料庫；備份目錄必須是既有非符號連結目錄，且由操作員限制存取。輸入不得指定伺服器路徑，快照檔名由伺服器隨機產生並拒絕覆寫。
- JSON 請求上限 5 MB、最多 500 筆對應；拒絕未知頂層欄位、多個 JSON 值、缺少工作階段、目的組織不一致及空重試鍵。所有業務資料與權限仍由交易重新檢查。
- 只在成功完成匯入及資源關閉後輸出成功；錯誤時回傳非零碼與不含秘密的通用訊息。若快照建立後交易失敗，快照保留在受限目錄供操作員檢查；不得刪除。
- 命令不提供互動式密碼輸入、不建立工作階段、不自行停止其他程序、不自動還原或切換資料庫。輸入來源和管線由操作員安全管理。

## 程式測試

先以隔離資料庫及記憶體輸入輸出測試：有效請求匯入一次、回傳非路徑快照識別並確認檔案存在；目的組織不符、超大輸入、未知欄位、多重 JSON、缺工作階段、無效路徑及非目錄拒絕；錯誤輸出與成功輸出均不包含 session 或備份資料；既有快照不覆寫；鎖衝突與失敗回滾繼續由協調器測試。Linux 和 Windows 遠端 CI 先 Red 再 Green，另以程序層測試確認入口退出碼與標準串流。生產演練不在此測試範圍。
