# 共用資料移轉：安全交付舊版備份

## 架構文件

影響系統：MES、ERP、POS、CRM、餐飲、電商，以及管理員資料移轉工作區。舊 Node 與新 Go 使用不同資料庫；切換新版前，使用者需要可檢查、對應、暫存、匯入並核對舊版資料。此功能不自動連接舊資料庫、不自動執行匯入，也不改動既有登入或公開站台。

流程：管理員選擇 v1 JSON → 伺服器檢查結構與租戶、列出衝突與所需身分 → 管理員選擇目標帳號 → 隔離資料庫暫存並核驗 → 明確確認來源與目的空間 → 受控維護窗口中建立目標庫快照 → 在同一交易重新驗證授權、輸入、衝突與業務限制，寫入資料與稽核 → 回報筆數與可供操作員查閱的備份識別資訊。既有帳號、權限、工作階段與歷史稽核不由舊資料覆蓋。

匯入前須在部署端排除其他服務或程序寫入目標資料庫。SQLite `data_version`、單一連線及寫入交易可偵測部分競態，但不等同完整維護模式；目前尚無已驗證的跨程序維護鎖。不得在此保障和還原演練完成前開放正式匯入或切換生產流量。

## 程式邊界

- 來源限制為已支援版本、已知業務資料表與既有大小上限；拒絕身分憑證、缺表、未知欄位、其他租戶、無法對應的身分、無效參照及不一致業務資料。
- 操作者需在六站均有啟用的後台管理員權限，交易內再次驗證有效工作階段與各站授權；不同租戶不得查詢或更改彼此資料。
- 不接受用戶指定伺服器檔案路徑；快照由伺服器於預先設定、受限的目錄建立且不覆寫。備份識別不能揭露主機路徑或授予其他租戶讀取權。
- 每次執行需重查目的地衝突，不依賴先前暫存結果；同一 idempotency key 相同內容只能產生一筆匯入及稽核，變更內容須拒絕。資料、稽核及重試紀錄須一併提交或回滾。
- 快照須在資料異動前建立並驗證；失敗不刪除快照，不可因錯誤將部分資料標記成功。必須提供經測試的操作員還原流程，但不自動覆蓋現行資料庫。
- 對大量輸入、逾時、磁碟不足、無效日期、重複鍵、授權變更、其他程序寫入及重試提出明確錯誤；匯入過程不將備份原文或憑證寫入日誌。

## 程式測試計畫

先以隔離資料庫和遠端 CI 撰寫行為測試：完整合法備份一次成功並可重算全部表與關聯；相同重試只成功一次、異內容重用鍵遭拒；目標衝突、無效身分、授權撤銷、其他租戶、資料不一致、快照建立／檢查失敗及寫入中斷均零部分寫入且保留原庫；前後台角色拒絕；有限大小與機密處理；維護鎖及停機／重啟／回復演練。使用者介面另驗證來源、目的地、對應、警告、確認、成功與錯誤狀態。Linux 和 Windows 均須驗證路徑與快照，使用真實資料副本而非生產資料。

## 目前進度

已有唯讀檢查、身分對應、隔離暫存、內部交易與快照候選；Windows 相容性與上述完整驗收尚在遠端 CI 中。尚未設計或完成可信任的跨程序維護控制、還原演練及可公開呼叫的正式匯入介面。下一輪先為維護窗口和還原制訂可執行的機制與測試，再實作；不能以文件或預檢通過取代交付。
