# 六站共用：離線匯入協調器

## 架構文件

離線匯入由具主機檔案權限的操作員執行，未來命令列入口將備份、身分對應、登入工作階段及明確目的組織傳給協調器。協調器先取得與站台相同的維護鎖，再開啟已存在的目標資料庫（不建立或遷移 schema），建立並驗證匯入前快照，最後以既有交易原子執行身分授權重驗、資料檢查、匯入、重試紀錄及稽核。工作結束後先關閉資料庫再釋放鎖。操作員須先停止所有未參與此鎖協定的服務與程序。

此輪先實作可測試的內部協調器，不開放 HTTP 或命令列入口，也不在生產環境執行。正式可用前仍需完成安全的輸入通道、備份路徑保護、操作員介面及離線還原演練。

## 程式邊界

- 指定的目標庫必須是已存在的普通檔案，不能使用 URI、記憶體庫或符號連結；鎖未取得不得開啟或修改資料庫，也不得建立快照。鎖僅約束協作程序，不宣稱阻止其他 SQLite 寫入者。
- 開啟目標時不得呼叫會執行 migration 的 `openDB`；以單一 SQLite 連線啟用必要約束，驗證既有應用 schema，不允許建立新庫。
- 快照目的地由可信任的內部呼叫者提供，不能既存；匯入或驗證失敗仍保留已建立快照。正式入口不得接受不受信任的遠端路徑。
- 使用既有工作階段及六站管理員權限，在寫入交易內驗證；所有資料、稽核與重試紀錄同時成功或回滾。不能透過日誌洩漏工作階段或備份內容。
- 返回筆數或錯誤；資源清理失敗必須回報。來源與資料庫保持租戶隔離，既有帳號與權限不被備份覆蓋。

## 程式測試

先在隔離暫存目錄寫測試並取得遠端 Red：同一目標被持鎖時拒絕且不建立快照；不存在或非應用資料庫不得建立／變更；有效登入與空備份成功且快照存在；無效 session、缺權限、資料錯誤與目的衝突回滾並保留快照；關閉後可再次取得鎖；不同組織和重試不混淆。Linux 與 Windows CI 執行；此階段不得用來宣稱生產可匯入。

Red：[遠端編譯紀錄](https://github.com/Davis1233798/profolio/actions/runs/41309015031/job/124855301893) 確認 `offlineImportLegacy` 未實作。其後已加入內部協調器；上述測試及完整失敗矩陣仍待遠端 Green，未開放外部入口。
