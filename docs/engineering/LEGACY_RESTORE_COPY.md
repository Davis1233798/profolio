# 共用資料移轉：建立可檢查的還原副本

## 架構文件

系統：六站共用 Go 資料庫的操作員還原工具。由操作員在隔離維護環境提供既有 SQLite 快照，工具以唯讀方式開啟並檢查，再以 SQLite `VACUUM INTO` 建立全新的還原候選檔，檢查候選檔後回報；不替換正在使用的資料庫，不自動啟動服務或執行舊資料匯入。候選經離線演練、核對資料及正式維護程序後，才可由操作員決定切換。

## 程式邊界

- 僅接受存在的普通檔案作來源；來源唯讀，不初始化 schema 或執行資料庫遷移。目的地必須不存在，任何既有目標均拒絕，包括與來源同路徑或硬連結。
- 保留 SQLite transaction 的一致視圖；來源或候選 `quick_check` 必須為 `ok`，且來源與候選均有應用程式 `organizations` 表。無效資料庫、無效路徑與被取消的工作必須回報失敗，不得更動來源或既有檔案。
- 僅建立候選檔，不可宣稱跨程序排他、原地還原、資料完整業務驗收或自動復原。失敗後若有建立部分目的檔，錯誤應明確提示操作員檢查，不能刪除可能由其他程序建立的檔案。
- Windows 本機磁碟機路徑和包含空白、特殊字元的路徑應可用；UNC 目前明確拒絕。禁止 UI/HTTP 使用者提交伺服器路徑，此工具僅供具備主機檔案存取權的操作員。
- 命令列 `--restore-copy <snapshot> <new-candidate>` 接受且只接受兩個路徑；錯誤以非零結束碼回報。它不使用 `SUITE_DB` 作為隱含目的地，也不替換服務資料庫。

## 程式測試

先寫隔離目錄中的行為測試：成功複製實際應用 schema 和測試資料；來源及輸出內容一致；修改輸出不影響來源；既有目的地、來源不存在、非 SQLite、非應用 schema、取消的 context 均拒絕並保留來源；特殊路徑於 Windows 與 Linux 測試。遠端 CI 先取得 Red，再實作並確認 Green；不在使用者機器本地執行測試。實體主機維護切換和完整業務還原演練仍需另行驗收。

命令入口另測試參數數量、來源與目的地為空、成功建立候選檔及不覆寫目的地。

Red：[遠端 Go 編譯紀錄](https://github.com/Davis1233798/profolio/actions/runs/41308072900/job/124852495613) 確認候選建立函式尚未實作；之後已新增命令與實作。Green 尚待遠端 Linux 與 Windows CI 驗證。

## 還原候選內容核對

架構：候選檔建立及完整性檢查後，以唯讀連線比較來源和候選的應用 schema、SQLite `user_version` 及每個一般資料表的全部列；對每列依 SQLite 型別與內容編碼並計算摘要，排序列摘要以保留重複筆數且不依賴 SQLite 儲存順序。只回報表名及失敗類別，不記錄資料原文或憑證。此檢查不是業務驗收，也不授權覆蓋正式資料庫。

程式邊界：來源必須為隔離、無外部寫入的既有快照；比較過程任一查詢失敗、schema 或資料不同、context 取消均拒絕候選，保留檔案供操作員檢查。納入一般資料表與自動維護的 `sqlite_sequence`，排除 SQLite 內部統計表；不支援虛擬表時明確失敗，不可靜默略過內容。比較必須不受資料列排序、NULL、blob、整數與文字差異影響，並尊重重複資料。避免將資料值輸出至日誌。

測試：先建立多表與重複列的 SQLite 資料，驗證相同資料可通過，不同列值、刪除重複列、schema、版本或 blob 差異均拒絕；測試取消 context 與真實 VACUUM 候選。Windows 與 Linux 僅透過遠端 CI 驗證。
