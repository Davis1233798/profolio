# 共用資料移轉：建立可檢查的還原副本

## 架構文件

系統：六站共用 Go 資料庫的操作員還原工具。由操作員在隔離維護環境提供既有 SQLite 快照，工具以唯讀方式開啟並檢查，再以 SQLite `VACUUM INTO` 建立全新的還原候選檔，檢查候選檔後回報；不替換正在使用的資料庫，不自動啟動服務或執行舊資料匯入。候選經離線演練、核對資料及正式維護程序後，才可由操作員決定切換。

## 程式邊界

- 僅接受存在的普通檔案作來源；來源唯讀，不初始化 schema 或執行資料庫遷移。目的地必須不存在，任何既有目標均拒絕，包括與來源同路徑或硬連結。
- 保留 SQLite transaction 的一致視圖；來源或候選 `quick_check` 必須為 `ok`，且來源與候選均有應用程式 `organizations` 表。無效資料庫、無效路徑與被取消的工作必須回報失敗，不得更動來源或既有檔案。
- 僅建立候選檔，不可宣稱跨程序排他、原地還原、資料完整業務驗收或自動復原。失敗後若有建立部分目的檔，錯誤應明確提示操作員檢查，不能刪除可能由其他程序建立的檔案。
- Windows 本機磁碟機路徑和包含空白、特殊字元的路徑應可用；UNC 目前明確拒絕。禁止 UI/HTTP 使用者提交伺服器路徑，此工具僅供具備主機檔案存取權的操作員。

## 程式測試

先寫隔離目錄中的行為測試：成功複製實際應用 schema 和測試資料；來源及輸出內容一致；修改輸出不影響來源；既有目的地、來源不存在、非 SQLite、非應用 schema、取消的 context 均拒絕並保留來源；特殊路徑於 Windows 與 Linux 測試。遠端 CI 先取得 Red，再實作並確認 Green；不在使用者機器本地執行測試。實體主機維護切換和完整業務還原演練仍需另行驗收。
