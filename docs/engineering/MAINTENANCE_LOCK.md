# 共用 Go 資料庫：維護窗口協調

## 架構文件

單台主機上，Go 站台伺服器及未來的離線匯入／還原切換命令，對同一資料庫旁的固定鎖檔取得排他鎖並持有至程序結束。使用 [gofrs/flock](https://github.com/gofrs/flock) 的非阻塞排他鎖，讓後啟動者明確失敗。服務持鎖期間持續提供既有 Web，維護程序需先由操作員停止服務；維護程序持鎖時禁止另一個遵循此協定的站台程序啟動。正常只讀快照指令不參與維護鎖，避免破壞現行部署前備份。

鎖只約束遵循本協定、使用相同標準路徑及相同檔案系統的程序；不阻止舊版本、直接存取 SQLite 的外部工具、不同硬連結或其他主機。正式匯入之前仍須停止所有非協定寫入者、確認部署的所有實例已升級、備份與還原演練完成。本輪不開放匯入，也不把協作鎖當成生產環境維護已完成。

## 程式邊界

- 以資料庫目錄解析後的絕對路徑及資料庫檔名形成固定 `.maintenance.lock`。不接受記憶體資料庫、URI 或指向其他檔案的符號連結作為共用鎖身分；多硬連結與網路檔案系統不承諾安全。
- 伺服器在初始化 SQLite 或背景 worker 前取得鎖，持有到關閉資料庫；取得失敗立即退出，不建立資料表、不監聽埠。鎖檔不能靠存在與否判定鎖狀態，不刪除鎖檔以免 inode 競態。
- 離線維護命令與伺服器共用鎖的取得邏輯；未來匯入在取得鎖後才建立快照及寫入。現有 `--backup` 和 `--restore-copy` 僅讀來源並建立新檔，不宣稱對來源取得維護排他。
- 鎖取得或釋放錯誤不得當成功；異常退出後由 OS 釋放。檔案目錄須由部署者保護，禁止不可信者替換鎖檔。
- 伺服器初始化採單一資源擁有者：先取得鎖，再開啟並遷移資料庫；關閉時先關閉資料庫，再釋放鎖。開啟或遷移失敗必須關閉已開啟的資料庫連線並釋放已取得的鎖。

## 測試計畫

先撰寫行為測試並在遠端取得 Red：同一資料庫第二個持鎖者遭拒、不同資料庫不互相阻擋、釋放後可重新取得、無效路徑拒絕；另以真正子程序測試程序退出後可重新取得、伺服器持鎖阻擋另一伺服器與維護模式。Linux 和 Windows CI 均執行，測試目錄隔離。驗證被拒時沒有建立或修改資料庫。維護鎖測試不取代未協作程序、跨主機或正式還原演練。

Red：[遠端編譯紀錄](https://github.com/Davis1233798/profolio/actions/runs/41308397540/job/124853461003) 顯示 `acquireMaintenanceLock` 尚未定義。其後已加入鎖定函式與伺服器啟動整合；跨平台 Green、實際伺服器衝突與維護模式端到端仍待遠端驗證。

下一輪先以伺服器初始化入口測試：已有持鎖程序時拒絕且不建立資料庫；成功開啟時其他程序不能取得鎖；關閉後可取得；初始化失敗也釋放鎖。遠端 Red 後再調整資源擁有與關閉順序。

生命週期 Red：[遠端編譯紀錄](https://github.com/Davis1233798/profolio/actions/runs/41308708571/job/124854393783) 顯示 `openStationDatabase` 未定義；其後已加入單一資源擁有者，遠端 Green 尚待驗證。
