# 真實業務 API 的隔離併發展示

## 架構與程式邊界

MES 與電商實際併發展示必須透過正式 Go 業務 API 與正式業務表；每次展示使用獨立臨時 SQLite 資料庫，建立隔離測試身分與虛構業務資料。不得在正式工作區資料庫建立無法清理的測試租戶，也不得將隔離 `traffic_records` 當成正式報工或訂單。正式展示功能須有可控的資料庫生命週期、明確授權、並行請求與最終業務表核對；模擬付款必須清楚標示。

第一輪先建立遠端 CI 的真實 API 交易證據：隔離檔案資料庫中，MES 管理員啟動工單，多個前台操作員請求競爭完整產量，核對工單上限、單筆報工與重試；電商對單件庫存併發 checkout，核對訂單、庫存與預留，同鍵重試不重複。請求使用正式登入、角色、租戶、API 與資料表，不藉由直接更新取代交易。測試結束由測試框架刪除臨時目錄；不得稱此為公開網路或多節點吞吐量驗證。

## 測試

先建立隔離組織，取得正式 API 工作單、工序和商品；對每個站點同時發送不同鍵的請求，核對成功數與衝突、正式資料表及冪等重試。確保另一租戶不受影響。遠端 GitHub CI 執行，不在使用者機器執行本機測試。後續仍需完成可安全操作、可觀測並可回收的後台展示介面及故障／逾時重試驗證。
