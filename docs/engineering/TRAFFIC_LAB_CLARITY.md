# MES／電商併發展示範圍與停止狀態

## 架構與邊界

目前工作台對實際 Go HTTP／SQLite 發送併發請求，但寫入隔離的 `traffic_runs` / `traffic_records`，不是 MES 正式報工、電商訂單、業務庫存或其履約事件。畫面首屏須清楚標示隔離交易實驗室，避免將其解讀為實際業務路徑。停止按鈕只阻止尚未開始的請求；已在途請求完成後，畫面顯示已停止及未送數量，不能稱整輪完成。傳輸或逾時錯誤不能推論伺服器未提交；須標為結果未確認並指向持久化台帳。

真正業務路徑的隔離壓測尚待設計與實作，必須使用隔離租戶及正式 MES 報工／電商交易 API，驗證正式業務表、庫存和冪等結果，不能以目前模擬台帳取代。

## 測試

先測請求總數、完成數與停止旗標決定未送數與狀態；遠端驗證英文／繁中標籤及 TypeScript。實際瀏覽器交互與真正業務路徑壓測另行驗收。
