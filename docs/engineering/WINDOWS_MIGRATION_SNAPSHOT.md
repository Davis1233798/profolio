# 共用資料移轉：Windows 快照相容性

## 架構文件

舊資料由使用者提供的備份進行唯讀檢查與隔離暫存；將來正式匯入前，Go 程式需在保留的單一資料庫連線上建立 SQLite 快照、以唯讀模式檢查快照，然後在同一連線交易內重新驗證身分、授權和資料，最後一起提交業務資料、重試紀錄與稽核。失敗保留快照並回滾交易。Node 與 Go 資料庫分開；此輪不開放匯入 API，也不執行正式資料遷移。

Windows CI 的 [執行紀錄](https://github.com/Davis1233798/profolio/actions/runs/41307408560/job/124850520442) 顯示快照完整性檢查失敗；另有測試尋找錯誤的 session cookie 名稱。快照唯讀 URI 的 Windows 磁碟機路徑是待驗證原因，不能在修復及遠端檢查完成前宣稱根因已確認。

[SQLite URI 規格](https://www.sqlite.org/uri.html)將 Windows 磁碟機絕對路徑表示為 `/X:/...`，並要求跳脫路徑中的特殊字元；`mode=ro` 指定唯讀開啟。此輪僅處理本機磁碟機路徑；網路 UNC 快照路徑不在驗收範圍，應明確拒絕而非轉成錯誤目的地。

## 程式邊界

- 輸入：可信任的本機快照目的地；不得覆寫既有檔案。Windows 磁碟機路徑與含空白、`#`、`&` 的路徑須正確轉為唯讀 SQLite URI。
- 交易：只接受單一應用資料庫連線；保留快照、檢查版本與完整性、失敗回滾。外部寫入者仍需獨立停止；不得宣稱已解決多程序協調。
- 身分：測試使用站台專屬 session cookie，不能以通用名稱假設登入成功；正式匯入仍須交易內重新檢查身分及六站權限。
- 不變動正式資料或啟用匯入端點；錯誤不洩漏資料內容。

## 程式測試與驗收

先寫會區分 Windows 磁碟機 URI、特殊字元及唯讀模式的測試，再修改 URI 建構。遠端 Windows CI 執行快照特殊路徑、既有快照拒絕、交易回滾、寫入競爭與成功匯入候選；Linux CI 執行 Go race。測試 session cookie 應以登入站台的名稱取得。記錄失敗與通過的 Actions run；尚未取得 Green 前本輪為進行中。使用者要求不在本地執行測試。

Red：[遠端執行紀錄](https://github.com/Davis1233798/profolio/actions/runs/41307705336/job/124851404604) 因 `legacySnapshotReadOnlyURI` 尚未定義而編譯失敗。已於 Red 後加入 URI 建構與站台 cookie 測試修正；Green 尚待遠端 CI 驗證。
